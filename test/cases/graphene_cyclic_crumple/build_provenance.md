# Cyclic Replay Oracle Extraction Notes

This directory contains two different cyclic oracle surfaces that must not be mixed:

- `simulator_run/`
  The archived stochastic canonical Fortran runtime outputs.
- `replay_step1_*.dat`
  Deterministic step-one replay fixtures captured from an instrumented Fortran replay path.

## Important Contract Boundary

The canonical Fortran runtime in
`../finite_crystal_elasticity/grapheneCompressionOriginVersion/pasapas.f90`
does **not** read `imperfection_trace.dat`.

Instead, on every cyclic load step it does:

```fortran
call random_seed()
if (imperfect .eq. 1) then
  call random_number(a)
  ...
end if
```

That means:

- a plain source-built canonical `crunch_it` replay on `prepro_run/` is **not** a same-trace replay
- its `energy.dat` / `force.dat` rows are useful as archived-runtime context only
- they must **not** be used directly to regenerate the deterministic `replay_step1_*.dat` fixtures

## Deterministic Replay Fixtures

The committed deterministic fixtures in this directory are:

- `replay_step1_trace.dat`
- `replay_step1_energy.dat`
- `replay_step1_force.dat`
- `replay_step1_before_first_eval*.dat`
- `replay_step1_before_output*.dat`
- `replay_step1_accepted_*.dat`
- `replay_step1_accepted_*_xfree.dat`
- `replay_step1_accepted_*_gfree.dat`
- `replay_step1_accepted_lbfgs_head.dat`

These fixtures were captured from a source-backed **instrumented Fortran replay path**
that reproduces the deterministic replay lane used by the C++ tests.

In particular, `replay_step1_energy.dat` and `replay_step1_force.dat` remain:

```text
       1     1   1  0.30445359E-03  0.30445359E-03  0.00000000E+00  0.00000000E+00  0.977273355D-05
       1     1   1      0.000022279      0.001250697
```

These rows are the deterministic replay contract currently exercised by
`E2ECyclicRuntime.CrunchItReplaysCommittedCyclicStepOneTraceDeterministically`.

## Element Oracle

The committed element-level oracle
`replay_step1_accepted_2_element3200_full_oracle.dat`
is generated by
`test/cases/tools/dump_cyclic_replay_element_oracle.f90`.

That extractor is source-backed and now honors the archived runtime contract from
`nano_general.dat`:

- if `nW_hat=0`, it keeps `eta` fixed and does not call `newton_inner`
- if `nW_hat=1`, it runs guarded inner relaxation and fails hard on nonzero `fail_mode`

## Current Status

- The deterministic step-one replay fixtures are still the active executable-path oracle for the
  cyclic replay tests.
- The plain source-built canonical runtime is now known **not** to be a same-trace oracle because
  it ignores `imperfection_trace.dat`.
- The live cyclic blocker remains the constrained-step runtime mismatch against the committed
  deterministic replay fixtures, especially on `GNORM` and reaction output.
